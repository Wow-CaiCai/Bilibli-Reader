日期：2026-10-04。审查基于 `codex/reader-enter-animation` 当前工作区，包含尚未提交的进入动画调整。

实施记录：用户已明确当前没有导出功能。随后重构移除了导出、Obsidian、隐藏面板与旧侧栏消息链；保留的公共 helper 改为 `utils.js`。阅读会话与布局分别拆入 `reader-session.js`、`reader-layout.js`，同时落地会话失效检查、字幕选择请求编号、监听解绑、布局与播放分离、拖拽帧合并、内容缓存及死代码清理。构建运行时桥拆为 `scripts/userscript.template.js`，默认构建不再递增版本。后续补齐剩余五项：删除无处理能力的 AI 快捷入口；新增 `page-observer.js`，按宿主范围统一监听，祖先只观察直接替换；章节与字幕各自缓存更新；高亮与滚动锚点复用节点索引；状态按视频、会话、偏好、播放器、原生字幕和 UI 分组，播放器兼容逻辑集中在 `reader-player.js`。启动调用移至全部模块初始化之后。以下诊断保留为重构前的会诊记录，行号对应审查时源码。

### 后续专家会诊与实施（2026-10-04）

再次基于重构后的代码交叉审查，落实以下优化：

- 删除无调用的 AI 字幕判断 helper、无消费者的视频简介链，以及 currentUrl、autoFoldedSignature、renderedKey 等只写状态。删除无消费者的时间戳可见性链和旧主题变量、退出按钮 active 样式；设置迁移清除废弃键，保留现有字体偏好和迁移版本。
- 证明阅读模式只有原生播放器布局，移除重复 nativePageMode 标记和不可达旧布局分支，以 open 条件保留退出阶段的保护。集中视频事件解绑和播放器、挂载计时器清理；入口只重置一次视口，避免两次异步恢复 scroll-behavior 相互覆盖。
- 播放器候选选择改为一次遍历，保留评分、同分顺序和异常尺寸兜底。页面观察区分内容变化与宿主拓扑变化；缺失宿主发现只探测缺失项，稳定范围不再定时重建。
- 原生字幕只写实际变化的字体、主题和控件属性，对齐与高度更新复用同一次播放器测量。保留原生字幕 250ms 跟随、原生 margin 归零测量和延迟宿主恢复。
- 同一视频、抓取编号和字幕请求编号下共享进行中的抓取，避免普通字幕加载与进入阅读模式重复发起请求。API 和字幕正文统一走请求桥，删除无调用路径的直接 fetch 分支与旧扩展上下文错误处理。页面请求增加 5 秒超时与取消信号，连同脚本管理器回退共用 20 秒预算；回退另有 watchdog，并尝试中止超时请求。

本次只做构建、语法及静态检查。功能测试交用户，未采样帧率、CPU 或内存，不承诺具体性能提升比例。下面仍为最初会诊的历史诊断。

## 结论

首要问题是生命周期与执行频率：播放器监听没有完整解绑，异步挂载缺少等待后的会话检查，播放同步反复进入布局逻辑。仅把大文件切成小文件，不能解决这些问题。

建议分小批落地：生命周期修复 → 播放与布局分离 → 拖拽调度 → 渲染缓存与观察范围 → 已证实的冗余清理 → 模块边界与构建整理。

## 第一批：修复生命周期与竞态

### 1. AI 入口的宿主监听器没有释放

- 证据：`src/player-integration.js:110–144` 给播放器 host 添加 `mousemove / mouseenter / mouseleave / pointermove`，闭包捕获入口 wrap。`:94–108` 移除入口时只删除 wrap、清计时器，没有解绑 host 监听。
- 触发：启用 AI 入口后，进入阅读模式移除入口；退出重新创建，再向同一个播放器 host 添加回调。旧回调继续持有旧 wrap。
- 建议：绑定函数返回 disposer，移除入口和换 host 时执行；若统一采用 pointer 事件，删除等价的鼠标移动回调。功能未启用时不要启动该功能的全树 observer。
- 判断：监听器残留可确认，累计内存和事件耗时未测量。不要把默认关闭功能造成的条件性问题描述成所有用户必现。

### 2. 阅读会话缺少统一的失效编号

- 证据：`src/reading-view.js:393–454` 只在挂载循环起点检查模式；`:409` 等待关闭迷你播放器后，`:411–431` 直接更新 host、样式和监听。`:1995–2001` 控件恢复等待后也直接继续操作。
- 风险：等待期间退出、重新进入或换视频，旧任务仍可能继续影响播放器。仅检查 `readingViewOpen` 不能区分退出后新建的会话。
- 建议：引入 `readerSessionId`，进入、退出和播放器会话重置时更新；每个异步任务捕获编号，在每次 await 后检查。挂载任务采用同会话单飞，控件恢复与待执行 rAF 一并取消。
- 边界：保留退出快照的延迟清理；不能在退出回调中提前清掉动画仍需使用的页面状态。

### 3. 同视频字幕选择需要独立请求编号

- 证据：`src/app.js:762`、`:1112` 和 `src/native-transcript.js:666` 都复用视频 `fetchRunId`。`src/app.js:790–871` 校验视频抓取编号，未校验字幕选择编号。
- 风险：同视频的两个字幕请求都可能仍然有效，后返回的旧请求可能覆盖新选择。控件临时 disabled 不能替代请求级正确性保证，其他入口和刷新也能发起加载。
- 建议：保留视频编号，增加字幕请求编号；只让当前选择提交状态、更新 loading/disabled。把缓存与网络分支的重复提交逻辑（`:820–831`、`:860–871`）提取为 `commitSubtitle`，在那里递增内容 revision。
- 判断：保护缺口可确认；实际复现概率需要交互验证。

## 第二批：降低重复布局与计算

### 4. 播放同步与布局分离

- 证据：`src/reader-playback.js:49–83` 每次同步先调用 `layoutReaderPlayerHost`。`src/reading-view.js:1272` 的 250ms 定时器和 `:1374` 附近的视频事件都会调用播放同步；暂停时定时器仍运行。
- 布局成本：`src/reading-view.js:1140–1182` 写列宽、读取几何、清宿主样式、写多处 CSS 变量、更新字幕占位并排队检查控制栏。
- 建议：播放同步只处理时间、高亮与跟随。尺寸、滚动、设置、宿主替换、挂载变化标记布局 dirty，通过统一 `scheduleLayout` 每帧合并处理；写入值未变化时跳过。
- 边界：保留播放器替换检测与低频恢复兜底。不能直接删所有轮询，因为 B 站会异步替换播放器。

### 5. 拖拽每帧只计算和提交一次

- 证据：`src/reading-view.js:854–870` 每个 pointermove 都执行布局；`:868` 调用列布局，`:869` 进入播放器布局后又在 `:1146` 调用一次。`src/bootstrap.js:311–326` 内部也有重复的列宽推导。
- 建议：只保存最新坐标，rAF 每帧处理一次；统一测量，复用同一份布局结果，再批量写样式；去掉重复调用，滚动锚点每帧恢复一次。
- 必须保留：pointerup 先 flush 最后坐标再保存偏好；退出、换视频和取消拖拽时撤销待执行帧。仅给每个事件套一个 rAF 并不能合并工作。

### 6. 减少全树 observer 被自身更新唤醒

- 证据：`src/bootstrap.js:631`、`src/native-transcript.js:6`、`src/player-integration.js:7`、`src/reading-view.js:1320` 都监听 body 子树。播放同步通过 `renderReadingStatus`（`src/reading-view.js:964`）反复写 textContent，触发 childList 观察。
- 建议：相同文本不写；按 mutation records 判断播放器、面板锚点、宿主替换或扩展节点删除是否相关；稳定宿主采用局部观察，全树观察只负责发现宿主变化，调度合并。
- 边界：不能简单忽略所有扩展节点变化，站点删除入口或字幕面板时仍需恢复。缩小观察范围比单纯把多个 observer 合成一个更重要。

## 第三批：让内容缓存真正生效

### 7. 规范化一次，变化时再渲染

- 证据：`src/reader-playback.js:86–114` 每 tick 线性扫描字幕并重新规范化章节；`:116` 索引不变仍查询节点、操作 class。
- 证据：`src/native-transcript.js:323–348` 在语言 renderKey 判断前就构造 options HTML；`:384–394` 在字幕 renderKey 判断前 map/filter 全量字幕。`ensureNativeTranscriptPanel` 的 `:142–143` 还可能通过已加载分支和自身连续调用渲染。
- 证据：`src/reading-view.js:581–667` 每次渲染重建字幕、章节和选集；`src/app.js:1119–1124` 在 loadSubtitle 已渲染后又请求渲染。
- 建议：在数据提交时缓存规范化字幕和章节，维护字幕、章节、轨道内容 revision；在全量预处理前判定版本。拆开元数据、控件、字幕、章节和选集更新；渲染时建立 index→DOM 映射，高亮索引不变直接返回。
- 正确性：仅用 URL、条数作为版本会漏掉同 URL、同长度的内容更新。字幕查找当前采用“首个覆盖区间”，直接改为普通二分可能改变重叠字幕行为；先检测有序且不重叠，再提供快路径，异常数据保留现有语义。
- 首轮不建议引入虚拟列表：连续正文、点击索引与阅读锚点会受到影响，应先降低无效计算与重建频率。

### 8. 导出按需生成

- 证据：`src/note-format.js:2–7` 每次加载字幕都生成 Markdown、SRT、TXT、预览；`src/app.js:825`、`:865` 在字幕就绪前等待衍生内容生成，启用热门评论时还可能等待额外请求。
- 建议：字幕提交与显示独立完成；在复制、下载或导出时生成对应格式，并按数据和设置版本缓存。隐藏预览无需跟随每次加载重建。`getPopupPayload()` 仍返回这些格式，需同时适配请求时生成，不能只删除 state 赋值。
- 边界：保留已有导出能力和时间戳行为；功能是否移除另行决定。

## 暂不整链删除

- **旧隐藏面板与导出代码**：`src/app.js:284–312` 构建旧面板，但当前没有添加 open 的入口。部分导出函数仍通过 runtime 注册，且 README 描述导出能力。先按需计算，再决定恢复可用入口还是正式移除能力。
- **扩展 options / AI / sidepanel 桥**：当前 userscript 后台桥只处理 settings 与 fetch-json，不能支持全部旧扩展消息。可明确区分能力、隔离不可用入口；不要因为名字有 popup 就删除 runtime，userscript 的进入菜单仍用 `dispatchRuntimeMessage`。
- **播放器恢复、字幕身份校验、稍后再看适配**：属于站点兼容和防止错字幕的逻辑。先统一入口、减少触发，保留行为。
- **字体、行距、内容宽度和设置迁移**：没有当前 UI 控件不代表不可达，持久化设置仍能影响结果。
- **旧 CSS 基线**：当前阅读页面仍继承部分基础布局、字体与背景，不可把前半段样式当作旧弹窗全部删除。

## 最后再整理模块和构建

先收拢清理函数：字幕数据清空、阅读模式属性清空、监听/定时器 dispose。`src/bootstrap.js:603–622` 与 `src/reading-view.js:525–564` 的属性清理集合不同，不能用简单替换改变退出动画边界。

逐步分出五个职责：视频与字幕数据服务、阅读会话、布局调度、字幕渲染与播放跟随、站点播放器适配。DOM 和句柄归会话，偏好归设置，视频数据归 clip，避免继续扩充 `src/bootstrap.js:54–162` 的扁平 state。

`scripts/build_userscript.py:103–107` 每次构建都会递增版本，`:360–363` 写回源码和文档。建议普通 build 只生成产物，bump/release 单独管理版本；先提取 userscript 运行时模板，再考虑模块打包。源码与 `Bilibli-Reader.user.js` 是源文件和生成产物的关系，不是应删的重复实现。

## 分批验收边界

测试仍由用户执行。每批分别核对：反复进出模式与快速换视频；等待挂载时退出；字幕切换与刷新交错；拖拽最后位置和阅读锚点；暂停播放、seek 与重叠字幕；普通视频与稍后再看；退出动画结束后的原生布局与控制栏；导出和旧设置迁移。

本轮未采样 CPU、内存或帧率，因此不承诺具体性能提升比例。优化目标是减少重复工作并保持现有可见行为。
